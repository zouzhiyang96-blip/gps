# 测试通信协议与后续指令入口

## 上报与业务确认

设备建立一个 TCP 连接，发送 ASCII 行，行尾为 LF。字段为十进制整数，设备 ID 为 24 位大写十六进制字符串，来自 STM32 UID。

```text
DATA,<device_id>,<sequence>,<battery_mv>,<wake_reason>,<boot_count>\n
ACK,<device_id>,<sequence>\n
```

示例中的 `\n` 表示一个换行字节，不是反斜杠和字母 n。唤醒原因按位定义为 BOOT=1、RTC=2、SENSOR=4，可以组合。

服务器在 SQLite 事务提交后发送 ACK。设备必须同时匹配设备 ID 与序号，才认为记录交付完成。`SEND OK` 只说明模块接受了发送操作，不代替业务确认。没有 ACK、ACK 不匹配或清除状态时掉电，都会保留记录并在下次唤醒重发。

首版只保留**一条待确认记录**。待发记录存在时，先复用其原始内容和序号，本次只重新测电压判断能否启动通信，不覆盖待发采样。它用于验证通信与恢复，不是完整离线轨迹队列。服务器按设备 ID 和序号去重，同一个 ID 对应不同内容时拒绝覆盖。

序号从 1 开始，达到保留上限时停止分配，避免回绕复用。软件更新应保留状态区；若要擦除状态或恢复出厂，需要设计新的登记代次或重置服务器身份，不能直接让旧 ID 的序号重新开始。

## AT 驱动

模块使用 buffer access 模式，依次执行 AT / ATE0、CPIN、CEREG、QICSGP、QIACT、QIOPEN、QISEND 和 QIRD。QIOPEN 的异步结果与命令 OK 分开确认，允许它们以任一先后顺序到达。

QIRD 按声明的原始字节长度读取，不把 TCP 负载内的 `OK` / `ERROR` 当作 AT 结果。原始负载交给增量行解析器，支持半包、连续多行和有界缓存。UART 错误、缓冲溢出或异常长度触发任务失败，不清除待发数据。

单次采集上报总预算为 180 秒，其中最多 150 秒用于通信和命令窗口，预留最多 30 秒关机。各 AT 步骤有自己的超时，均不能突破总预算。这些是原型策略，不承诺任意网络一定在该时间内联网成功。

ACK 到达后继续读取约 2 秒，以收集后续完整命令帧。周期读取 QIRD，不依赖收到新的 recv 通知，因此不会因模块已经有未读数据而丢失后续读取机会。

## 指令占位

```text
CMD,<command_id>,<opcode_decimal>,<argument>\n
CMD,42,1,\n
```

`protocol.c` 负责长度和数字范围校验，每次最多暂存 4 条命令，每条参数最多 48 个字符。`commands.c` 负责分发表，十进制 1 是只读 PING 占位，其他指令返回 `COMMAND_UNSUPPORTED`。当前结果只进入本地调试日志，**尚未实现远程命令结果回传、持久去重或参数修改**。

将来增加指令时，需要一起增加：

1. 权限与身份认证、有效期及重放控制。
2. 参数结构、幂等语义和执行期限。
3. 状态持久化、重启恢复和失败结果。
4. RESULT 等执行回执及服务器结果跟踪。

新增处理函数可放入 `.command_handlers`，在 0x080C0000 的保留区域扩展。状态页、未来配置区和应用区均已通过链接脚本隔离。保留空间不意味着已经具备 Bootloader 或 OTA。

这是实验用自定义明文协议，不兼容 Tracksolid Pro / 原厂 LL702，也没有 TLS。首版不传位置、不开放会修改设备的远程控制。生产接入必须先完成认证、加密和命令安全设计。
