# 首次联调

## 上电前

1. 确认目标为 STM32L476RG、1 MiB、双 Bank、未交换 Bank，SWD 可用。此工程不要直接下载到 LL702。
2. 按 hardware.md 连接供电、天线、SIM 和双向电平转换。核对外部负载开关、PWRKEY 驱动及其低电平默认状态。
3. 先使用受控实验电源，确认模块发射峰值时没有压降重启，再评估一次电池。没有真实 ADC 分压输入时，固件会跳过通信。
4. 在自己的测试服务器准备 TCP 9000 端口，确认设备所在蜂窝网络可以访问。电脑的 127.0.0.1 不可直接填给模块。

## 第一次上报

1. 启动 `tools/test_server.py`，记录服务器的实际地址和数据库文件位置。
2. 复制本地配置示例，填入运营商 APN、服务器和端口。调试阶段启用 USART2 日志，并使用 60 秒休眠间隔。
3. 获取固定驱动并构建。用 ST-LINK 下载 `gps.hex`，冷启动后观察服务器是否新增一条 DATA。
4. 检查固件 `app` 中的状态、错误码及 `state.pending`，核对服务器 ACK 的设备 ID 和序号。
5. 确认关机后 PB0 变低，UART 引脚进入模拟态，RTC 约一分钟后重新唤醒。也可给 PB12 一个低到高的测试边沿。
6. 断开调试器并关闭调试串口，再用覆盖微电流和发射峰值的仪器测整板。先验证电源确实关闭，再讨论续航。

## 失败实验

- 服务器加 `--drop-ack`：记录已经保存，但设备应仍保留 pending。取消该选项后再运行，重发相同记录，数据库只保留一行。
- 暂停服务器或使用不可达地址：设备在有限超时后关闭模块，不得持续尝试联网。
- 在写入或清除 pending 时断电：下一次启动应恢复旧的有效副本。已收到但未清除的记录可以重发，服务器去重。
- 在受控供电范围内使 ADC 电压低于所设门限：通信模块保持关闭，待供电满足条件再恢复。
- 若初始化或状态区损坏导致停止上报，先用调试器定位原因，不自动清空身份和序号。修复/重置需与服务器登记流程配合。

## 软件验证及实机边界

本版已提供主机 C 测试和 Python / SQLite / localhost TCP 测试，同时可以为 STM32 交叉编译。主机测试使用模拟外设，不验证真实射频、SIM、波特率、电源时序、ADC 校准和整板功耗。尚需真实 STM32 + 模块完成上述检查，才可称为可用硬件样机。

当前没有 GNSS 坐标采集、UTC 时间同步、完整轨迹缓存、成熟报警去抖、硬件看门狗、TLS、生产凭据、远程升级或可恢复 Bootloader。指令入口为只读原型，尚不承诺结果回传。后续应分阶段增加，避免把占位接口当作已有功能。

调试日志不调用标准输入输出文件接口，只有 `port_log()` 通过 UART2 输出。活动期间串口发送采用最多 100 ms 的有界阻塞，AT 和任务等待使用状态机。不要在运行状态机之前关闭 HAL 活动时基。
